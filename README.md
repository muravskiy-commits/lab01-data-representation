## 1. Мета лабораторної роботи
Експериментально дослідити, як комп'ютер представляє різні типи даних у фізичній пам'яті, як одна й та сама послідовність бітів змінює своє значення залежно від типу, що відбувається на межі діапазону беззнакового типу та який порядок байтів (**endianness**) використовує система.

**Головне питання лабораторної роботи:** *Що насправді знаходиться в пам'яті комп'ютера, коли програма працює з числом або символом?*

---

## 2. Очікувані результати
Після виконання лабораторної роботи студент повинен уміти:
* використовувати оператор `sizeof()` для визначення розміру типів даних;
* пояснювати зв'язок між кількістю бітів і діапазоном значень;
* представляти число у системах **decimal**, **hexadecimal** та **binary**;
* пояснювати різницю між **signed** та **unsigned** інтерпретацією;
* пояснювати поведінку `unsigned integer` при переході через межу діапазону;
* пояснювати зв'язок між символом та його числовим кодом ASCII;
* досліджувати окремі байти багатобайтового значення у пам'яті через вказівники;
* визначати порядок байтів системи (**Little-endian** / **Big-endian**) експериментально.

## 4. Результати кожного експерименту

### Завдання 1. Розміри типів даних (`types.c`)
За допомогою оператора `sizeof()` визначено кількість байтів та бітів, які виділяються під базові типи даних у 64-бітному середовищі Linux (модель даних LP64).

| Тип | Розмір, bytes | Розмір, bits |
| :--- | :---: | :---: |
| `char` | 1 | 8 |
| `short` | 2 | 16 |
| `int` | 4 | 32 |
| `long` | 8 | 64 |
| `long long` | 8 | 64 |
| `float` | 4 | 32 |
| `double` | 8 | 64 |
| `void *` | 8 | 64 |

**Відповіді на питання:**
1. **Чи всі типи займають однакову кількість пам'яті?** Ні, розмір залежить від типу даних і становить від 1 байта (`char`) до 8 байтів (`long`, `long long`, `double`, `void *`).
2. **Скільки бітів займає `int` у вашому середовищі?** **32 біти** (4 байти).
3. **Який розмір має вказівник `void *`?** **8 байтів** (64 біти).
4. **Що розмір вказівника говорить про архітектуру середовища?** Розмір вказівника 64 біти свідчить про те, що програма працює на **64-бітній архітектурі (`x86-64`)**, де ширина адресної шини віртуальної пам'яті становить 64 біти.

### Завдання 2. Decimal → Hexadecimal (`representations.c`)

| Decimal | Hexadecimal | Binary |
| :---: | :---: | :---: |
| `10` | `0xA` | `00001010` |
| `65` | `0x41` | `01000001` |
| `127` | `0x7F` | `01111111` |
| `255` | `0xFF` | `11111111` |
| `256` | `0x100` | `00000001 00000000` |
| `1024` | `0x400` | `00000100 00000000` |

**Пояснення: Чому `65`, `0x41` та `01000001` представляють одне й те саме значення?**  
Комп'ютер зберігає у пам'яті виключно фізичний стан бітів (`01000001`). Десятковий (`65`) та шістнадцятковий (`0x41`) записи — це лише різні системи числення для зручного відображення одного й того самого кількісного значення:
$$6 \cdot 10^1 + 5 \cdot 10^0 = 4 \cdot 16^1 + 1 \cdot 16^0 = 2^6 + 2^0 = 65$$

### Завдання 3. Виведення бітів (`binary.c`)
Реалізовано функцію `print_binary(unsigned char value)` з використанням побітового зсуву та маски `(value >> i) & 1u`:
* `0` ➡️ `0x00` ➡️ `00000000`
* `1` ➡️ `0x01` ➡️ `00000001`
* `10` ➡️ `0x0A` ➡️ `00001010`
* `65` ➡️ `0x41` ➡️ `01000001`
* `127` ➡️ `0x7F` ➡️ `01111111`
* `128` ➡️ `0x80` ➡️ `10000000`
* `255` ➡️ `0xFF` ➡️ `11111111`

**Чому функція починає перевірку з біта 7, а не з біта 0?**  
Консоль виводить символи зліва направо. У позиційній системі числення зліва записується **старший значущий біт (MSB — біт 7, вага $2^7$)**, а справа — **молодший значущий біт (LSB — біт 0, вага $2^0$)**. Якби цикл починався з `0`, двійковий запис вивівся б у дзеркальному порядку.

### Завдання 4. Символ — це також число (`characters.c`)

| Character | Decimal | Hex |
| :---: | :---: | :---: |
| `'A'` | `65` | `0x41` |
| `'B'` | `66` | `0x42` |
| `'a'` | `97` | `0x61` |
| `'0'` | `48` | `0x30` |
| `'9'` | `57` | `0x39` |

**Що фактично зберігається у змінній `char c = 'A';`?**  
У пам'яті зберігається ціле число **`65`** (`01000001` у двійковій системі). Комп'ютер не зберігає графічних образів літер — специфікатор `%c` у `printf` просто перетворює число `65` у символ `'A'` згідно з таблицею кодування **ASCII**.
